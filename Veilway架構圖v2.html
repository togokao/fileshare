隱道Veilway

所有 AI 請求都走同一條道：送出前在平台內把個資換成代號，回覆回來後再換回真名。外部模型從頭到尾只看得到代號。

v2（2026-10-07）：出口改走 PrivateLink、補上推論位置的查證結果、檢查點處理規則，以及特殊合規租戶的建議；隱道閘道改為獨立的 ECS service。

全景：隱道在系統中的位置

前台、業務 API、資料庫都是標準配置。整套架構跟一般 SaaS 不同的地方，在於後端唯一能連到平台外模型的出口，就是隱道閘道；它是獨立的 service，有自己的 security group 與 IAM role。

檢查點：攔下之後怎麼辦

檢查點掃描「準備送出的最終文字」，檢查三件事：對照表裡已登記的原值又出現了、格式固定的個資漏網、租戶字典裡的名字出現了。

情況處理
對照表裡的原值沒換掉自動補遮後重送，使用者不會感覺到
高信心命中（身分證、卡號）自動補遮；補遮後仍命中就 fail-closed，拒絕送出
低信心命中（如「林立」）依租戶政策：嚴格的租戶直接拒絕；一般租戶讓使用者勾選「這不是個資」後送出，並記下這次放行
檢查點故障或逾時一律 fail-closed，不能因為檢查服務壞了就放行

限制：NER 第一次沒認出來的名字，檢查點多半也認不出來。檢查點防的是程式出錯，不是第二層 NER。每次攔截都寫入稽核紀錄（類型與處理方式），但不記錄命中的原文。

出口與推論位置

以下依 Anthropic 官方文件查證（2026-10）。

項目結果
VPC endpoint支援 AWS PrivateLink。閘道經 VPC endpoint 連線，endpoint 的 security group 與 policy 只允許閘道，呼叫權限只授權給閘道的 IAM role
區域所有 AWS 商用區域皆可用；workspace 建在台北區域，只能從台北端點存取
推論位置inference_geo 只有 global（預設，全球任一 Anthropic 資料中心）與 us（只在美國，價格 1.1 倍）；沒有台灣或亞太選項
AWS 區域的作用只決定端點與 IAM、CloudTrail、帳單的範圍，不決定推論在哪裡
資料保存位置不可設定，目前為 us
資料處理者Anthropic；保留政策同第一方 API，零資料保留（ZDR）需另外申請

結論：端點在台北，推論與保存在境外。這正是隱道要解決的問題：出境的只有代號，對照表留在台北。對外說法統一為「平台在台灣，只有代號化後的內容出境」，不說「資料都在台灣」。代號化屬於假名化，仍算個人資料，服務條款與租戶合約需揭露推論位置與資料處理者。

有特殊合規要求的租戶：建議自建地端 AI

租戶若要求資料（即使已代號化）不得出境、推論必須在特定地點或處理者的設施內進行，或受主管機關對委外與跨境傳輸的限制（例如金融、醫療、公部門），平台不提供境外模型，而是建議租戶在自己的機房架設地端 AI，平台經隱道連接器接過去。

為什麼這樣建議

  1. 只有地端能完全做到資料不出境。推論位置只有 global 與 us，沒有台灣選項；對最嚴格的租戶，代號出境本身就可能不被接受。
  2. 不涉及第三方資料處理者。地端由租戶自己營運，不需另簽資料處理協議或評估跨境傳輸。
  3. 不必另外維護第二條雲端路徑。改走 Bedrock 也是選項，但要多維護一套模型 ID 與功能差異，而且仍在租戶的控制之外。
  4. 架構已經預留。隱道連接器只需改 endpoint，依路由政策導向地端，業務程式碼不必修改。
  5. 回答品質可以更好。模型在租戶機房時，可依租戶政策不做遮蔽，模型看得到完整上下文。

取捨（要先講清楚）：地端模型能力通常不如 Claude；GPU、維運與更新由租戶負責；平台只保證連接器與路由的正確性。
